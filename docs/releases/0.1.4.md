# ICOR for Life - Terminal 0.1.4

A single fix release. It finishes the keyboard work 0.1.3 started by
clearing the one cosmetic item that release named. Nothing about how the
terminal runs has changed.

## Fixed

- **The pane menu no longer offers to release a keyboard it is not
  holding.** In a pane whose shell has exited, and on Windows where no
  pseudo-terminal exists, the keyboard item now reads `Keyboard not
  captured, no running shell` and is disabled, and the toggle command says
  the capture arms the next shell instead of claiming the keys. 0.1.3
  gated the capture itself but left both strings reading the setting
  alone, so a pane that had already handed the keyboard back still offered
  to release it and still announced that it held the keys.
  Ian Slattery's Windows report surfaced the family.

## Not in this release

- A shell that survives an Obsidian reload is still a detached helper, and
  still a 0.2 decision.

## Security posture

Unchanged. No new process family, no new permission, no change to how the
helper is started: it still runs in Python's isolated mode (`-I`), pinned
by `test/helper-isolated.test.mjs`, and every condition of the 0.1.0
security review stands.

## Install

Copy `main.js`, `manifest.json` and `styles.css` from this release into
`.obsidian/plugins/icor-for-life-terminal/` and enable the plugin in
Settings, Community plugins. Requirements and the Windows scope are
unchanged from 0.1.0.
